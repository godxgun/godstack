PeakIOCode#

Source: Peak.h:511

typedef enum {
    PEAK_IO_OK, PEAK_IO_INVALID, PEAK_IO_LIMIT,
    PEAK_IO_NOT_REGULAR, PEAK_IO_UNSUPPORTED, PEAK_IO_SYSTEM
} PeakIOCode;

Safe I/O (independent of peak_init): Linux openat2 only; other hosts and kernels lacking the required resolution flags return PEAK_IO_UNSUPPORTED. No fallback to ordinary path-based I/O. Native Windows/macOS qualification is pending. Legacy peak_file_* / peak_filesystem_* retain their semantics.

Ownership: initialize caller storage with *_INIT before first use. Successful opens/begin fill an empty output; failures leave it empty. These are owning, non-copyable values, not borrowed descriptors. Do not edit their fields, close their native handles yourself, or use them concurrently with close. Close consumes a handle even on error; commit/abort consume both stage handles on every outcome for a live stage. Separate objects may be used concurrently; operations on a stage must be externally serialized.

Paths: root_open takes an absolute path ("/" is allowed); all *_at/open/begin paths are nonempty normalized relative paths. No empty, dot, dot-dot, or symlink components, trailing slash, or absolute relative paths are allowed. Limits: 4095 path bytes, 255 bytes/component, 128 components, byte limits representable as a native nonnegative file offset. No heap allocations. Every relative lookup is kernel-resolved beneath its owning directory handle with RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS. Mount points/hard links are not rejected: these are not authorization, provenance, or immutable-snapshot primitives. Files are verified regular.

Handles pin directory/file objects, not pathnames. Root or parent rename/ replacement does not redirect an existing handle. A retained directory may be moved outside the original tree; later operations still target that object, not the current object at its former path. Reads are bounded but not snapshots: uncooperative in-place writers can change bytes/size during a read. size is only the initial observed file size; hash/validation policy and coordination with writers belong to the caller.

Staging: destination’s parent MUST be cooperatively/exclusively controlled against uncooperative directory writers (including same-user writers). A named stage is not safe against such writers swapping/unlinking its name between creation, rename, and cleanup. temporary_leaf is caller-selected, single-component and distinct from destination’s leaf; O_EXCL never reuses an existing entry. Use an appropriately unpredictable/reserved name and authorize/serialize the destination yourself. The stage is visible by its temporary name (mode 0600), so callers must exclude stages from asset lookup. Commit atomically replaces a non-directory destination entry via renameat; it does not follow a destination symlink. No no-clobber/version checks, metadata preservation, backups, or multi-file/bundle transaction policy. Previous-file preservation on failure applies only within the cooperative contract; external races are not covered. All stages are same-parent.

Bounded read is positional, reports partial progress on failure and EOF via read_bytes < bytes. It rejects a currently observed size above limit, but cannot detect every transient growth or mutation. Stage writes are sequential and bounded in aggregate; any invalid/failed write poisons publication. Successful commit without durability only establishes publication. With FILE_AND_DIRECTORY, fsync(stage) precedes rename and fsync(parent) follows; durable=1 means both succeeded, subject to filesystem/hardware guarantees; durable=0 means durability was not established, not that bytes were lost. This does not fsync ancestor directories or establish durability of newly created directory hierarchies. Byte bounds are not elapsed-time deadlines. A post-rename error NEVER means unpublished: inspect published separately. published is 0 (not attempted/not published), 1 (rename succeeded), or -1 (rename failed ambiguously; e.g. a lost remote FS reply). Destination type/ nonempty-directory errors are definite failures within the cooperative contract; other rename errors are conservatively reported as uncertain. Do not interpret -1 as false or true; recovery must inspect/coordinate the destination. On uncertain publication the temporary name is not removed. Cleanup reports unlink/close failures independently; a failed pre-publication cleanup may leave the temporary name for caller-managed recovery. No rollback after publication. Cleanup success does not establish crash-durable removal of a temporary name. Invalid finish arguments leave the stage untouched.

PeakMemoryDomain#

Source: Peak.h:766

typedef enum {
	PEAK_MEMORY_NON_DRIVER = 0,
	PEAK_MEMORY_DRIVER,
	PEAK_MEMORY_DOMAIN_COUNT
} PeakMemoryDomain;

Direct instrumented backing calls only, not libc/DSO or Vulkan internals. Single-threaded diagnostics; counters persist for the process lifetime. Each domain has independent fixed live-pointer capacity (512 by default). Exhaustion leaves request counters valid, but live/release evidence incomplete; live_blocks/live_bytes/peak_bytes are not exact when tracking is incomplete. Unknown-pointer operations invalidate BOTH domains’ accounting: original ownership is unknowable. Request counts remain useful but uncertified. Overflow saturates counters and clears accounting_complete. No reset API. PEAK_DEBUG_MEMORY_TRACE (default 0) enables per-request output.
